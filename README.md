# CUFA PHOTO CONTROL

Google Sheets + Apps Script + GitHub Pages 的拍攝現場工作站。

- `index.html`：總控台
- `index.html?view=checkin`：報到台（唯一可新增人員的入口）
- `index.html?view=student`：手機資料填寫，盲送待核對區，不提供名單查詢
- `index.html?view=slate`：棚內電子試鏡單，學號與姓名最大
- `index.html?view=call`：姓名叫號，與棚內拍攝狀態分開

## 後端

`apps-script/Code.gs` 對應原始拍攝表格 `1EhDDUVQ-Jvn9v9LXLLYYemBBlZ7dcEZAmfJQrJ6XJpw`。初始化函式 `setupPhotoControl` 僅補上缺少的工作表與欄位，保留原始名單與既有 `ADMIN_PASSWORD` Script Property。先執行初始化與 `testPhotoConnection`，再部署新版本，將 Web App URL 寫入 `config.js`。

Apps Script 必須以擁有者執行，允許未登入者呼叫，才可從 GitHub Pages 送出表單。後端只開放驗證格式後的學生資料送出；完整名單、電子試鏡單、叫號與所有工作操作均須通過 `ADMIN_PASSWORD`。密碼只留在 Script Properties 與工作站 sessionStorage，不放入版本庫。工作站閒置後請登出或關閉分頁。

學生送出不是報到。工作人員核對待核對資料並儲存後，再按報到發號。重複報到保留原號碼。形象照需同意書檢核才能報到及拍攝；勾滿所有拍攝項目後才可完成。補拍會重設勾選，保留備註。暫緩與回待拍不改號碼。

`ActivityLogs` 保留時間、操作與工作站名稱（共享密碼下的工作站名稱不是經身分驗證的個人帳號）。號碼分配與狀態寫入使用 Script Lock 避免多工作站重複發號。Sheets 多列寫入並非資料庫交易；網路失敗後應重新同步確認。學生表單以 requestId 避免同一次送出重試重複新增。

每六秒讀取同步，編輯備註時暫停重繪。儲存一組任務時會一起儲存目前所有任務，避免其他備註遺失。斷線顯示同步中斷；拍攝前請確認試鏡單最新時間。

## 驗證

`node tests/backend.test.cjs` 驗證密碼、同意書、發號、重複報到、叫號／棚內分離、完成門檻、補拍及表單冪等性。使用合成測試人員，不修改正式名單。

首版限制：單一攝影棚、共享工作人員密碼、六秒輪詢；未提供離線操作與個別角色帳號。學生表單不等同電子簽署，同意書需現場另外檢核。

## v2 更新

拍攝名單一列只對應一種拍攝。`splitShootWorkflows` 將原本同時拍兩種的人員拆為兩筆，以既有任務列為依據，保留 taskId、勾選與備註。試鏡照保留原人員 ID，形象照使用 `__image` 後綴。原先已報到的第二種拍攝會取得新的不重複叫號號碼。兩筆基本資料共用同一學號，編輯時同步身高、體重、手機等基本欄位；報到、同意書及任務狀態各自獨立。

報到頁由工作區與原始名單決定拍攝類型，不能在報到視窗變更。試鏡照不顯示也不要求肖像權檢核。現場新增時沿用目前工作區。

總控流程為等待 → 叫號 → 進棚拍攝。進棚必須對應目前叫號者，進棚後清除該叫號卡，避免重複顯示。系統仍採單一棚內拍攝者。試鏡單顯示手機，姓名／學號為大字，其餘資料為中等字級。

後端在單次請求內快取已讀資料表，更新時不用重讀整張表；讀取總覽另使用 20 秒 Google Script Cache，手動「重新同步」可跳過快取，修改後立即清除並更新快取。工作頁只在目前工作站 sessionStorage 留存最近畫面，登出清除；切換工作頁先顯示最近畫面再向伺服器更新。首次 Apps Script 冷啟動仍取決於 Google 服務。

## 2026-11-01 v3

總控與報到使用同一份清單，原表每筆拍攝類型與任務保留。`saveCheckIn` 在一次請求中驗證與儲存資料、同意書收件、報到及發號，回傳姓名／號碼收據。`finish` 一併驗證及儲存所有任務；暫緩保存現有項目及備註後回待拍。寫入先於請求內整併，再每個資料表批次送出，避免同一人的連續儲存請求。Google Sheets 跨表仍非資料庫交易；網路錯誤後請重新同步確認。

`LiveControl.callQueue` 為依序加入的 personId JSON 佇列，第一位相容 `calledPersonId`。重複叫號不改順序；第一位進棚後移出佇列，叫號畫面顯示下一位。單一實體棚內仍只容許一位。暫緩、請假會移出叫號佇列。未完成的勾選與備註會在本頁的其他叫號操作後保留。

流程進度讀取原表「拍攝流程」的 slotId/start/end/title/kind，對照台北時間，可指定時間預覽。班級依拍攝類型與班級對應，個人依姓名對應形象照；不匹配名單及重疊時段明列提醒。班級預定量依時間比例估算；請假扣除，老師隨到隨拍不計預定量。這是每天時段比較，表內沒有活動日期欄，並非歷史日期追蹤。既有完成任務計入實際量，測試資料未自動重置。

登入只需現有密碼，稽核來源自動記錄為總控台／報到台等頁面名稱。學生手機頁仍保留連結可用，但報到頁已移除推廣卡片。電子試鏡單顯示手機、分開的身高與體重；全螢幕標題留出左側控制區。
